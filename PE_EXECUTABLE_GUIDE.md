# Windows PE Executable Guide

## Overview

CRAB can compile C# code to Windows PE (Portable Executable) format, which is the native executable format for Windows. This guide explains how PE executables work and how to use them properly.

## Understanding PE Executable Behavior

### Why PE Executables "Close Immediately"

When you double-click a PE executable generated by CRAB on Windows:

1. **Expected Behavior**: The console window opens, the program runs, and immediately closes
2. **This is NOT a bug**: This is normal behavior for console applications
3. **Why it happens**: The program completes execution and exits, closing the console window

**Example:**
```csharp
// This program will appear to "close immediately"
class Program
{
    static void Main()
    {
        System.Console.WriteLine("Hello World!");
        // Program exits here, console closes
    }
}
```

### How to View Output

There are several ways to see your program's output:

#### Option 1: Run from Command Line (Recommended)
```cmd
# Navigate to your project directory
cd MyProject\bin

# Run the executable
.\output.exe

# Or with CRAB run command
crab run bin\output.wat --format pe
```

#### Option 2: Add a Pause (Temporary Solution)
```csharp
class Program
{
    static void Main()
    {
        System.Console.WriteLine("Hello World!");
        
        // Keep console open
        System.Console.WriteLine("Press any key to exit...");
        System.Console.ReadKey();
    }
}
```

#### Option 3: Use Output Redirection
```cmd
# Redirect output to a file
output.exe > results.txt

# View the file
type results.txt
```

## PE vs Native Format

CRAB supports two executable formats:

| Format | Platform | Description |
|--------|----------|-------------|
| **native** | Linux/Unix | ELF executable format |
| **pe** | Windows | Portable Executable format |

### Automatic Format Detection

When you use `--format native`, CRAB automatically:
- Generates **ELF** executables on Linux/Unix/macOS
- Generates **PE** executables on Windows

```bash
# On Linux: generates ELF
crab compile Program.cs --to-asm --format native

# On Windows: generates PE
crab compile Program.cs --to-asm --format native
```

### Explicit Format Selection

You can explicitly choose the format:

```bash
# Force PE format (Windows executable)
crab compile Program.cs --to-asm --format pe --output program.exe

# Force ELF format (Linux executable)
crab compile Program.cs --to-asm --format elf --output program

# Use native (auto-detects platform)
crab compile Program.cs --to-asm --format native
```

## Testing PE Executables

### Using the Test Command

The test command automatically uses the correct format for your platform:

```bash
# Quick test (single architecture, native format for your platform)
crab test --quick

# Comprehensive test (all architectures and formats)
crab test
```

On Windows, this will test both native (PE) and explicit PE formats.
On Linux, this will test native (ELF) and PE formats (PE won't execute but will compile).

### Expected Test Output on Windows

```
Testing x86_64 (native)           ✅ PASS
Testing x86_64 (pe)               ✅ PASS
...
Attempting to run on current platform...
  Detected platform: x86_64
Warning: Program exited with code: 42
  ✅ Execution successful on x86_64
```

The "Program exited with code: 42" is **normal** - this is the return value from the program.

## Troubleshooting

### "Program closes too fast to see output"

**Solution**: Run from command line instead of double-clicking.

### "Can't execute PE file on Linux"

**Expected**: PE files are Windows executables and won't run on Linux (without Wine).
Use `--format native` or `--format elf` on Linux.

### "Exit code 42 shown as warning"

**Not a problem**: Exit code 42 is the test program's return value (0x2A in hex).
Non-zero exit codes are shown as warnings, but this is expected for test programs.

### "PE file won't run on Windows"

**Possible causes**:
1. Missing Windows runtime libraries (should not be needed for CRAB-generated code)
2. Antivirus blocking execution
3. File corruption

**Solution**: Try rebuilding:
```bash
crab build --verbose
```

## Advanced: PE File Structure

PE files generated by CRAB include:

- **DOS Header**: MZ signature and DOS stub
- **PE Header**: PE signature and COFF header
- **Optional Header**: Image metadata and entry point
- **Section Table**: Code section (.text)
- **Code Section**: Your compiled machine code

You can inspect PE files with tools like:
- `dumpbin` (Visual Studio)
- `objdump` (MinGW/Cygwin)
- PE Explorer (third-party)

## Best Practices

1. **Always test from command line first** before distributing
2. **Use WASM format for browser deployment**
3. **Use native format for best compatibility** on each platform
4. **Document expected output** for end users
5. **Add proper exit codes** for error handling
